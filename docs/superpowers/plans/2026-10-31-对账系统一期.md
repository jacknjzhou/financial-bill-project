# 对账系统一期（phase-1-core）实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 交付一期对账系统核心：文件上传解析 + 交易对账引擎 + 结果查看 + 差错处理 + 工作台，全栈可部署（docker compose 单机），OpenAPI 在线文档。

**架构：** Django 5（DRF）REST 后端 + Vue 3 前端；对账执行为 Celery 异步任务（队列+多 worker+beat 定时），Web 与引擎解耦；PostgreSQL 16 存储，Redis 7 作 broker；文件落本地卷 `/data/files`。

**技术栈：** Python 3.11 · Django 5.x · djangorestframework · drf-spectacular · Celery · Redis · PostgreSQL 16 · openpyxl · pytest/pytest-django · Vue 3 + TypeScript + Vite + Element Plus + Pinia · Playwright（e2e）

**规格：** `docs/superpowers/specs/2026-10-31-对账系统-design.md`（执行者两份都读）

**分支：** 开工第一步 `git checkout -b phase-1-core`；全部任务完成后合并 main 并打 tag `v1.0.0-phase1`。

## 全局约束

（每条来自规格，所有任务隐含包含；数值逐字照抄）

- 金额一律**分**（int64 存储），前端展示换算元（`/100`，两位小数）
- 时区统一 Asia/Shanghai；时间存 UTC，**对账日期 = 交易时间转本地后的日期**
- **全部端点必须有类型化 schema**：状态/类型参数用 Choice 枚举、金额 int64（分）+描述、日期 ISO 格式、查询参数 `@extend_schema` 显式声明（名称/类型/取值/描述）、分页统一 `PageResponse`；新增端点不带完整 schema 视为不合格
- 对账结果必须可追溯到源数据行（明细接口内嵌 A/B 两方原文）
- 重对幂等：结果先删后写在同一事务；已处理差异保留引用不重复生成
- 同一（对账项目, 对账日期）并发触发只允许一个成功，其余 409
- 坏文件整批回滚：任一行不过则整批不入库，错误定位到行号（显示前 100 行）
- 同名同任务同日文件重复上传拒绝（409），显式覆盖重传除外
- 单文件上传 ≤ 50MB
- 初始账号 `admin/Admin@123` 首登强制改密；operator 无"系统管理"与"解析规则"写权限
- 解析整批入库、文件重复上传、并发执行等写操作全部幂等或带明确冲突语义（409）
- 后端测试依赖（pytest 等）进 `requirements.txt`（镜像内可跑 `pytest`）
- **后端标准 Django 结构（用户钉死）**：src layout——`backend/manage.py` + `src/financial_bill/` 项目包（settings/urls/wsgi/asgi/celery）+ 全部业务 app 统一放 `src/apps/` 目录；`INSTALLED_APPS` 用 `apps.core`/`apps.accounts`/… 形式；`DJANGO_SETTINGS_MODULE=financial_bill.settings`（manage.py/pytest 均先把 `src/` 加入 `sys.path`）
- **登录模式（用户钉死）**：本地账号密码与 OIDC SSO 两种登录并存（登录页两者皆可选）；本地账号密码始终可用，SSO 由 `OIDC_ENABLED` env 开关控制（默认关，关闭时 SSO 按钮隐藏、回调 404）；IdP 参数（issuer/client_id/client_secret/scopes）全部 env 驱动，代码不写死任何企业 IdP；SSO 自动建号的用户本地密码初始未设，可自助设置（免旧密码）或由 admin 重置
- commit 规范：conventional commit，中文描述（如 `feat(引擎): 匹配算法——对平/单边/错账`）

## 审查重点（Review Focus）

（规格未明写、但最可能伤到使用者的五类输入；每行对应一个钉住它的测试，已写入负责任务）

1. 上传文件的表头行/列名与解析规则对不上（新渠道模板变化）→ 解析失败、错误指向具体列、已有数据不受影响 → T7 `test_header_mismatch`
2. 文件内同一订单号出现两行（重复行）→ 解析拒绝并列出行号，不产生脏数据 → T7 `test_duplicate_keys`
3. A/B 两方时间跨日边界（23:59:59 vs 次日 00:01）→ 对账日期归属确定，绝不错日匹配 → T10 `test_reconcile_date_boundary`
4. 金额带两位小数（0.1+0.2 型浮点陷阱）→ 转分后精确整数，无 ±1 分漂移 → T7 `test_amount_precision`
5. 同一获取任务被两人同时上传 / 同一项目同日被并发触发 → 不 500、不重复，明确 409/201 → T8 `test_concurrent_upload_same_task`、T9 `test_concurrent_trigger`
