## 二、发现的缺陷（按严重度）

### 🔴 P0 — 不修必翻车

1. **T15 seed/e2e 数字不自洽**：A 60 行 = 38 对平 + 8 单边A + 9 错账 = 55 ≠ 60；B 55 行 = 38 + 5 + 9 = 52 ≠ 55。照此播 seed，e2e 断言必挂且排查困难。
   ✅ 已修：改为 **40 对平 / 10 单边A / 5 单边B / 10 错账**（A=60 ✓，B=55 ✓）。
2. **事务内 `.delay()` 竞态（T8/T9）**：`create InFile → parse_file.delay(id)` 与 `create_run → run_reconcile.delay()` 都在事务提交前投递，真实 worker 会在行提交前捞到任务（eager 模式下测试发现不了，上生产才炸）。
   ✅ 已修：统一改为 `transaction.on_commit(...)`。

### 🟠 P1 — 高概率出问题的设计缺口

3. **T10 匹配"消费语义"未定义**：A 命中 B 后若不从索引弹出，两条 A 同单号会同时命中同一 B → 写库撞 `partial unique (project, b_id)` → IntegrityError → run failed。B 同键多行且 `b_sum=False` 的行为也完全未定义。
   ✅ 已修：钉死"逐行弹出消费"语义；`b_sum=False` 多行 → 整组 wrong 落库；补 `test_duplicate_a_keys`、`test_multiple_b_no_sum`（审查重点新增第 6 条）。
4. **1vN/多行错账的可追溯断链（反目标级）**：ReconcileResult/Dispute 只有单个 `a_id/b_id` FK，聚合组内其余 B 行在结果与差错里都无引用，点不开 → 违反"结果必须可追溯源数据行"反目标。
   ✅ 已修：ReconcileResult 加 `group_no`（同组共享，A 一条 + B 每行一条），Dispute 幂等键改为 `(project, date, group_no)`，详情/处理按组聚合；补 `test_b_sum_group_traceability`。
5. **`status_mismatch` 无处落库**：匹配接口声明"状态不符时 diff 记 0 并另带 status_mismatch 标记"，但 ReconcileResult 模型没有这个字段——错账差异金额为 0 时无法区分金额差/状态不符。
   ✅ 已修：加 `diff_type choices[none,amount,status]`，补 `test_wrong_both`。
6. **覆盖重传可静默删除已对账数据（反目标级）**：`?overwrite=true` 直接删旧数据重解析，若该文件数据已进对账结果/差异，引用即断。
   ✅ 已修：源数据 FK 与 ReconcileResult/Dispute 全部 `on_delete=PROTECT`，已被对账引用 → 409；补 `test_overwrite_after_reconcile_409`（审查重点第 7 条）。
7. **CSRF 首次登录死锁**：client.ts"从 cookie 取 csrftoken"，但首次进登录页浏览器还没有 csrftoken cookie，login 必 403。
   ✅ 已修：加 `GET /api/v1/auth/csrf`（ensure_csrf_cookie），前端启动先种 cookie。

### 🟡 P2 — 细节修正

8. **allauth 配置错误**（T2B）：`allauth.oidc` 这个 app 不存在（应为 `allauth.socialaccount.providers.openid_connect`）；provider key 是 `openid_connect` 而非 `OIDC`，配置格式是 APPS 列表（`server_url/client_id/secret`），非 `OIDC_OP_issuer_url`。照抄必装不上。
9. **nginx 默认 1MB 上传限制**：nginx.conf 未设 `client_max_body_size`，50MB 需求直接 413。已补 60m。
10. **文件编码硬编码 utf-8-sig**：银行/部分渠道文件常为 GBK。ParseRule 加 `encoding` 字段 + utf-8 失败回退 gb18030。
11. **金额转换截断**：`int(Decimal(raw) * scale)` 对三位小数费用项会静默丢分。统一 `quantize(ROUND_HALF_UP)`（已写入全局约束）。
12. **Alert 模型依赖倒置**：T9 的 `alerts.py` 引用 T13 才建的 Alert 模型。已把 Alert 挪到 T9 建，T13 只做查询/标读。
13. **并发测试写法陷阱**：两线程并发用例在默认 `TestCase` 事务包裹下线程间互不可见，测不出真并发。已注明必须 `@pytest.mark.django_db(transaction=True)`。
14. **T2 测试计数 5→6**（步骤 1 列了 6 个测试）；T12 文件清单"修改"→"创建"（disputes app 首次出现）；T8 计数 8→9。
15. **T11 的"已处理/待处理"两列依赖 T12 物化数据**，已注明先按结果聚合实现、T12 接入后对齐。
